# PDF view navigation — October 7, 2026

Implemented source in `src/pdf-view-navigation.js` and its CSS. Reader integration remains owned by the parent task. Runtime testing is deferred at the user's request.

- Zoom to region is a temporary, view-only pointer overlay. It switches continuous, facing or readable-text views to Page view explicitly; the old reading view is available in Previous view history. Eight-pixel minimum drag in both dimensions; Escape, blur, pointer cancellation or a changed page/render cancel the overlay. Existing text-selection and measurement tools must be finished first. Hand mode is restored after the temporary tool finishes.
- Region coordinates are converted through the actual PDF.js viewport to PDF coordinates and back, preserving crop origins, rotation and user units. Rendering stays owned by PdfReader, with its 16-million-pixel limit and manual zoom bounded to 25–300% (the pixel limit may require a lower zoom). The chosen region is centered after successful rendering; no document bytes change.
- Up to 50 previous/next views retain physical page, fit width/page or manual zoom, reading view, view rotation and scroll position. Intentional navigation creates entries; resize and background render do not. Current manual scrolling is captured before the next intentional navigation. Starting a new branch discards forward entries. History is session-only and reset when document or artwork-fullscreen presentation changes; fullscreen intermediate renders are excluded.
- Exact hooks: construct `reader.viewNavigation = new PdfViewNavigation(reader)` after artwork fullscreen and canvas navigation; call `viewNavigation.rendered({page,viewport})` at the successful end of single-page rendering. Surround intentional go, zoom/fit/rotate actions and changeReadingView with `const token = viewNavigation?.begin(); ... await ...; viewNavigation?.commit(token)`. Commit after success only; nested latest-token commits prevent duplicate entries. Do not hook renderPage/resize. In fullscreen transition finally blocks, after busy becomes false, call `viewNavigation?.presentationChanged()`. Call `viewNavigation?.sync()` after initial toolbar enabling and `dispose()` before fullscreen disposal. Region/history internal transactions suppress those hooks while restoring.
- Continuous scroll alone does not create one entry per page. History is scoped to a single presentation context; it does not request native fullscreen transitions or promise exact scroll restoration after a window resize changes fit scale.

Source syntax check only; no runtime tests, launch or visual inspection performed for this feature.
