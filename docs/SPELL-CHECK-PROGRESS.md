# Local spell-checking progress — F46 / R45 / R46

The source implementation uses the Windows Spell Checking API and already installed language providers. It needs no paid API, subscription, feature unlock, dictionary download or document upload. Windows x64 and an installed supported language dictionary are required. A missing helper or unsupported language produces an explicit explanation; there is no remote fallback.

## Implemented source

- `desktop/native/LocalSpelling.cs` exposes fixed JSON `languages` and `check` operations through the Windows COM spell-checker factory. It calls `ISpellChecker.Check` and `Suggest`, returns UTF-16 offsets and bounded suggestions, and has no API for changing or registering Windows dictionaries. Each request owns and releases its COM interfaces on the STA thread. No renderer-supplied file path is accepted.
- `desktop/local-spelling-service.cjs` validates the pinned helper manifest, source SHA-256, executable SHA-256, request-bound response, offsets, exact source words and suggestions. Text is limited to 100,000 UTF-16 units per call, native findings to 400 and suggestions to eight per finding. Native requests are at most 800,000 UTF-8 bytes and output at most 1 MiB.
- The native helper attaches itself to a one-process Windows job with a 256 MiB memory limit and ten seconds of process CPU time. It checks the actual spawning parent and keeps an open process handle to detect parent death. The service enforces a 15-second wall deadline, bounded pipes, cancellation and observed process exit. A helper whose termination is not observed within five seconds closes the service to further work.
- Personal words live in a main-process-selected PDFix storage file. Saves replace a language list atomically through a newly created temporary file, with symlink checks, serialized writes, a 2 MiB file limit, 10,000 words per language and 20,000 overall. The editor supports adding, editing and clearing words. Personal words and session ignored words are matched by NFC normalization and lowercasing, then filtered locally. Windows `Add`, `AutoCorrect`, dictionary registration and global dictionary edits are never called. Personal words are accepted during checking but are not injected into Windows suggestion lists.
- `src/spell-check-workspace.js` provides language selection, explicit local checking, source-bound findings, suggestion replacement, ignore once, ignore all, reset ignored words, personal dictionary controls, cancel and departure cleanup. It scans sources in bounded chunks, up to one million UTF-16 units and 1,000 displayed findings. Reaching a native or workspace limit is reported as incomplete review. Suggestions are rendered as text. Replacement callbacks recheck current revision, text and edit permission before invoking the source editor.
- `src/document-spelling.js` provides optional TipTap underline decorations and paragraph-to-ProseMirror source mappings. Code blocks, inline code and embedded atoms are blanked in check text. Decorations clear on any document edit, so previous results cannot label newly edited words. Identifiers, source/code, formulas, paths and receipt inputs remain opted out by default; a prose-control helper makes the choice explicit.
- Read-only PDF review uses page-number segments and a locate callback. The generic workspace disables replacements for a read-only snapshot and never changes PDF text, permissions, font compatibility or source bytes. Supported PDF editing must still pass the application's existing edit checks.
- `src/document-text-tools.js` connects Spell check and Read aloud toolbar buttons to modal panels. Opening preserves the captured selection and fences it by file identity and editor revision. Source/code text requires an explicit opt-in checkbox. Rich spelling replacements validate paragraph mapping, original word, edit state, document structure and recovery size, then dispatch normal Undo/recovery transactions. Source textarea suggestions allow replacement only when native `insertText` and `delete` commands are advertised; the modal briefly releases its focus boundary for the synchronous command, retains native Ctrl+Z, and never falls back to assigning a replacement value. Otherwise replacement is disabled with a reason. Source revision changes and restored versions invalidate spelling and stop speech; departure/disposal awaits tool cleanup before destroying the editor.
- Document read aloud supplies captured-selection or whole-document text in at most 4,096-character chunks and 128-chunk/200,000-character batches, preserving UTF-16 offsets and revision-bound continuation cursors. The editable document does not expose physical page extraction, so Current page is explicitly labeled PDF-only and disabled; page requests explain the limitation. Rich code blocks/inline code remain excluded. Source/code read aloud is available only after explicit inclusion.

## Integration contract

Construct `LocalSpellingService` in the trusted main process with `{helperPath, dictionaryPath}`; neither path comes from a renderer request. The default helper path is `dist/native/local-spelling/PDFix.LocalSpelling.exe`. `dictionaryPath` must be an absolute app-owned file under user data. Expose only the following renderer calls through the existing validated owner-window IPC boundary:

| Renderer method | Main service method | Value |
| --- | --- | --- |
| `localSpellingLanguages()` | `languages({signal})` | `{languages:[{tag,label}],provider,notice}` |
| `localSpellingCheck(request)` | `check(request,{signal})` | Request `{text,language,revision,ignoreWords?}`; response `{revision,language,findings,truncated,provider}` |
| `localSpellingDictionary()` | `dictionary()` | `{version:1,languages:{[tag]:words}}` |
| `localSpellingUpdateDictionary(request)` | `updateDictionary(request)` | `{language,words}` replaces that language's complete list; empty list clears it |
| `localSpellingCancel()` | `cancel()` | Waits for observed exit, returns whether cleanup completed |

Dispose the service when its owner closes. A finding is `{start,length,word,action,suggestions}` with action `suggest`, `replace` or `delete`. Empty replacement text represents deletion. A revision is an integer or nonempty bounded source-identity string; the service echoes it and the source UI checks it again before editing.

Construct `SpellCheckWorkspace(root,{getSnapshot,applyReplacement,onLocate,onFindings,announce,api})`. `getSnapshot` returns `{text,revision,sourceLabel,segments?,readOnly?,reason?,optOut?}`. PDF segments are `{start,end,pageNumber}`; editable-document segments also include `from`. `applyReplacement({revision,start,length,word,replacement})` must use the editor's ordinary Undo/recovery transaction and return false if it refuses the edit. `onLocate(finding,snapshot)` receives a page number where available. `onFindings(findings,snapshot)` connects editor underlines. The panel exports `open`, `check`, `sourceChanged`, `prepareDeparture` and `dispose`.

Rich editors can register `DocumentSpellingHighlights`, produce text using `documentSpellingSnapshot(editor,revision,label)`, map a finding using `documentSpellingRange(snapshot,finding)`, and render findings through `setDocumentSpellingHighlights(editor,findings,snapshot)`. The source adapter must fence edits against stale revisions and use its existing recovery size limits. Source/code text can use an explicit opt-in; native input checking must still be bounded.

## Verification and acceptance limits

Source-only verification completed: `node --check` on the service, builder, workspace, document extension, document text-tools adapter and document editor; the native helper compiled with the installed .NET Framework compiler using `/warnaserror+`. `scripts/build-spelling-helper.mjs` builds the helper and writes the manifest and notice. Compiling does not execute the native helper or enumerate dictionaries.

Per the source-first instruction, no runtime/native/PDF/UI/dictionary tests, fixtures, installation or new test files were run or created. Native COM interoperability, installed-provider behavior, language matching, cancellation/parent-death acceptance, personal dictionary persistence, editor Undo/recovery and PDF page navigation remain unverified until runtime acceptance is authorized. This is implemented source toward F46/R45, not complete Acrobat parity or a tested release claim.

## Microsoft API references

The interface identities and COM method ordering were checked against Microsoft's [Windows SDK spellcheck header](https://github.com/microsoft/win32metadata/blob/main/generation/WinSDK/RecompiledIdlHeaders/um/spellcheck.h). The [spell-checker factory](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nn-spellcheck-ispellcheckerfactory) lists installed supported languages and creates a language-specific checker. [SupportedLanguages](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nf-spellcheck-ispellcheckerfactory-get_supportedlanguages) returns specific language/dialect tags. [ISpellChecker](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nn-spellcheck-ispellchecker) supplies checking and suggestions; [ISpellingError](https://learn.microsoft.com/en-us/windows/win32/api/spellcheck/nn-spellcheck-ispellingerror) supplies the location, corrective action and replacement. PDFix keeps personal words separate rather than invoking Windows dictionary mutation methods.
