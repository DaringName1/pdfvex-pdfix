# Cross-document page staging

Saved October 7, 2026. Adopted F07 is coded for explicitly chosen local PDF sources; current app/runtime acceptance remains deferred.

**Fix or combine pages** now has a collapsible **Copy or drag pages from chosen PDFs** tray. The native existing PDF picker can load a source into the tray without inserting its pages. Existing **Add another PDF** still appends all its pages. The source selector shows loaded originals; physical source-page buttons are paged in windows of 50. Clicking a page selects it, and dragging it copies its physical source mapping. The tray uses lightweight page identity controls rather than artwork thumbnails; actual artwork is reviewed in the existing generated-output preview.

Drop onto an insertion line before an output page, or append after the last page. The visible proposal identifies the source physical pages, current insertion boundary, resulting output positions and page counts. Expand its mapping to inspect every output page's original filename and physical page number. Confirm commits only the staged arrangement. Cancel keeps the previous arrangement, and Undo/Redo reverses confirmed changes. Nothing is exported automatically and original byte snapshots are never changed.

Output rows also have a **Move** handle. Drag it to reorder a page, or click it and choose an insertion position with the keyboard. Existing crop, resize, and rotation settings move with that output page. Source copying starts from the original physical page with its normal source orientation; existing staged edits are not silently applied to a fresh source copy. Keyboard users can choose source ranges (for example `1–3, 5`), enter an insertion position, review, confirm, or cancel. The last insertion position appends. Existing duplicate/remove/rotate/up/down controls remain available.

Drag data is accepted only from this workspace's private session token and captured internal selection, not from arbitrary operating-system files or another window. Proposal/drag revisions and exact source-object identities reject stale selections after source replacement, recovery/workflow load, undo, reset, or another arrangement change. Busy, saving, departing, recovery-blocked, preserving-reorder, child split, and geometry dialogs block staged edits. Edge scrolling during a valid internal drag helps reach positions inside the bounded output scroller, and pending animation is canceled on drag end/close. No external URL, drop path, or raw transfer page index is trusted.

Inputs remain at most 10 explicitly selected PDFs and 100 MB combined; each source and arranged output is bounded to 500 physical pages. Source-only loading can work when the current output is full, while confirming copies that would exceed 500 pages is refused. Loading another source remains in the session after undoing its page insertion; undo reverses arrangement changes, not authorized source loading. Existing saved arrangement/recovery schemas retain all selected source identities and physical page mappings. Reset can refuse if all loaded originals would exceed the 500-page output limit.

The existing safe writer, output preview, original comparison, independent geometry/page checks, and explicit new-copy saving remain in use. Existing warnings about dropped annotations, links, bookmarks, metadata, unsupported forms/signatures/protected PDFs, and crop not being secure removal still apply. This feature does not claim broader unknown-data preservation or native cross-window document drag support.

Files: `src/page-source-tray.js`, `src/page-source-tray.css`, `src/page-workspace.js`. No new dependency, main/preload IPC, native writer, or persistence contract was added. JavaScript source syntax checks passed. No app, browser, fixture, export, or native worker test was run; the root agent owns combined compilation and future acceptance.
