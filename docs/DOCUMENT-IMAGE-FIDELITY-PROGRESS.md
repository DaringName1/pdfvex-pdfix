# Inline document images

Saved implementation, 2026-10-04. Runtime testing remains deferred by user request. This checkpoint is code and syntax verification, not a claim of full Word fidelity or verified image rendering.

The document workspace now provides an actual PNG/JPEG file chooser and inline image nodes. Users can select an image, change preferred width/height, keep the source aspect ratio, set alternative text, fit it to a useful default size, remove it and Undo. Images follow paragraph alignment. They fit the available line/cell width while retaining the requested display ratio; floating/wrapped Word positions are not reconstructed. Image insertion freezes the document during worker processing, supports cancellation, blocks navigation/export until completion and validates the complete next document before dispatch.

Selected images and supported embedded DOCX PNG/JPEG images are decoded locally in the existing document worker and normalized to static embedded PNG assets. Normalization strips the source image container metadata and uses the decoder's observed orientation. Images that exceed the embedded asset budget are resampled in a bounded sequence, with the source and resulting pixel dimensions disclosed. No remote image URL is fetched. DOCX image conversion is serialized so only one image is decoded at a time; decoded bitmaps are closed and canvases released. Unsupported, inaccessible, oversized or over-count DOCX images are omitted with an explicit import count and explanation; originals are unchanged. Arbitrary remote/unsupported clipboard image references become a visible insertion placeholder. The sanitizer accepts only validated PDFix embedded image descriptors.

DOCX export writes real inline PNG image runs with dimensions and alternative text, including images in supported table cells. Preferred image width is clamped to page or cell space. Native document PDF HTML now includes validated data-only images, awaits successful image decoding and confirms actual natural dimensions before printing. Its CSP permits data images without allowing remote image resources. PDF export can handle image-only documents, and the existing PDF.js reopen step also checks for image paint operators rather than requiring readable text in an image-only result. This checks for image content presence, not pixel-exact image preservation. Review every exported page as before.

The same image descriptors are validated in recovery drafts/version history, initial editor JSON, editor transactions, DOCX output and native PDF output. The native image validator mirrors the browser model. Its small bounded cache stores only geometry of previously validated immutable source strings, so ordinary typing does not repeatedly decode every embedded base64 image. TXT and RTF use descriptive image placeholders; they do not retain raster content.

Bounds: source PNG/JPEG up to 5 MB and 4 million pixels, dimensions at most 8,192 pixels on either side; no animated PNG or nonstandard JPEG coding modes. Each normalized PNG asset is at most 512 KB. A document contains up to 20 images and 12 million normalized image pixels, and remains within the existing 2 MiB rich document/recovery limit, 20,000 nodes and depth 64. Display dimensions are 8–2,000 pixels and alternative text is at most 500 characters. Header/chunk geometry bounds run before browser decoding; the actual decoder remains responsible for complete compressed-image validity. The existing worker timeout is 60 seconds. This worker is not an OS sandbox.

New files: `src/document-image-model.js`, `src/document-image-codec.js`, `src/document-images.js`, `src/document-images.css`, `desktop/document-image-validation.cjs`. Updated document editor/worker/codec/HTML sanitizer/table transaction filter/RTF codec/PDF preview and native document PDF/recovery modules. No new dependency or IPC API is needed; native PDF results add the informational `imageCount` field through the existing route.

Required later runtime verification includes user-selected insertion/cancellation, JPEG orientation, PNG alpha, downsampling notices, DOCX image/table import and export/reopen, alt text and sizing, image-only PDF creation, native image decoding timeout/cancellation, recovery/Undo, malformed or remote clipboard references and all stated bounds. Full Word wrapping, cropping, original placement/extent, vector/animated media, image editing tools, original table widths and page-perfect layout remain open. No app, worker, browser or native print path was launched for testing during this checkpoint.
