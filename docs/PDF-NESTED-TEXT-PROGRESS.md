# PDFix nested original-text editing — saved implementation

Updated 2026-10-04. This is a saved source implementation; runtime acceptance remains deferred.

The original-text inventory now follows Form XObjects actually invoked by supported page/Form `Do` operators. Supported unmarked text inside explicit-resource, bounded, indirect Forms appears in the existing original-text list with a Nested label and resource path. It uses the owning Form's font resource, font size and source glyph mapping. Form text without an explicit supported font selection is omitted; inherited graphics-state font guesses are not used.

Nested IDs combine the physical page/offset with a SHA-256 digest of the exact source PDF SHA-256, Form resource path, original Form reference and string offset. Existing direct-run IDs stay unchanged. Renderer and native recovery validators accept the bounded optional nested suffix, and recovered edits must match the current source inventory. Root updated the native validator; no new IPC API is needed.

Replacement changes only the selected original string token spans in the decoded Form program. Existing fonts and observed source glyph codes are reused. Multipart TJ string operands retain their numeric spacing adjustments. Missing or ambiguous glyphs are refused; font substitution, paragraph reflow, shaping and new glyph embedding are not implemented. Added text remains a separate existing tool.

One shared edit session now handles nested text and image replacements. Each selected page/Form path is cloned once. Parent/child text replacements and image changes can coexist using those same clones; references do not point to an earlier stale clone. Original shared Form/image objects remain retained and hashed. Other named branches and pages retain their original references. All uses through the selected path on that page change; individual draw-occurrence editing remains open.

The reopened copy must preserve the selected source-font graph and encoded font programs at the actual nested font resource path. It must retain original Form/image objects, exact final encoded Form programs, original resolved BBox/Matrix/FormType geometry, unrelated Form dictionary fields and non-XObject resources, declared final XObject mappings and unrelated indirect root resource references. Each edited nested Form is independently decoded after reopen and must match the declared edited program length and SHA-256. Existing PDF.js output extraction/operator-list/layout review remains in the product preview code. These implemented gates have not been executed as runtime tests in this slice.

Bounds remain eight Form levels, 20,000 invoked resource paths, 1,000 Form paths, 2,000 candidate text strings, 200 staged edits, 2,000 characters per replacement, 8 MiB per decoded stream and 64 MiB aggregate decoded text. Shared clone budgets are 16 MiB per original Form and 64 MiB aggregate cloned bytes. Existing CMap/font/program/source/page limits remain enforced. Font observations are committed only for accepted candidate strings; refused branches do not expand the editable glyph repertoire.

Cyclic, direct, external/reference Forms, missing/inherited Form Resources, singular/oversized geometry, ambiguous escaped resource names, inline-image content streams, unsupported fonts and marked-content text are refused or omitted. Structural/text operators require valid operand shapes and balanced graphics/text/marked-content structure. A malformed page content sequence is omitted rather than inheriting unknown state into nested edits. When one named Form is invoked both within marked content and outside it, that path is withheld. Unsupported-path notices appear in the editor.

Compression parameters and derived Length/DL hints are recalculated/removed for changed program streams; unrelated source fields remain. Original objects are kept in the new copy, so replacement is editing and is not permanent redaction. Encrypted, protected/certified, signed and XFA refusal behavior remains unchanged. The original source file is not overwritten.

Saved files: `src/pdf-original-text.js`, `src/pdf-original-font-map.js`, `src/pdf-original-image-path.js`, `src/pdf-content-output.js`, `src/pdf-content-model.js`, `src/pdf-content-workspace.js` and this document. The shared path helper is reused by existing image operations. Root owns the combined build. All six edited JavaScript modules pass targeted syntax checks; no app, worker, browser or other runtime test was launched.

Source decisions were checked against the installed primary pdf-lib object/dictionary/stream/resource implementation and the existing source font-map/parser helpers. No external SDK or executable PDF/PostScript content was introduced.

Later hidden runtime gates should cover nested Type1/TrueType/Identity-H fonts; parent/child/sibling text plus image changes; repeated/shared Forms across names/pages; multipart TJ/literal/hex strings; exact source mismatch; recovery/Undo; retained font/program bytes; independent nested text extraction and visual appearance; malformed/marked/inherited/inline/cyclic/external path refusals; and source/clone/decode budget exhaustion. Full shaping, new glyphs, inherited-resource text, individual occurrences, tags/ActualText adaptation and complete unrelated-object equivalence remain open requirements.
