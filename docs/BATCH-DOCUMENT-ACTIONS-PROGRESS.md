# Batch PDF copy/rename and supported literal text

Saved October 7, 2026. Adopted F27 expansion is coded; app/native/runtime acceptance is deferred.

The batch workspace chooses 1–10 PDFs (100 MB combined) through the native picker and stores immutable, hashed `SearchSources` snapshots. Choose **Copy / rename PDF copies** or **Extract supported literal text to TXT**, edit each single output filename, choose a parent for a new batch folder, and process one item at a time. Each item pauses for action/name/output review before explicit save. Copy/rename creates a bit-identical new PDF, preserving encryption, signatures, attachments and every other source byte; original names/content are unchanged and no signature/safety verdict is implied. This operation performs no document parser work.

Text extraction uses the fixed contained `batch-pdf-text` operation. Its child codec parses bounded content objects/operators and resolves declared font resources; it never scrapes parenthesized text with regex, executes actions, fetches external resources or guesses font encoding. The deliberate current subset is unencrypted/unannotated plain page content using nonembedded built-in Type1 Helvetica/Times/Courier fonts with explicit WinAnsi encoding. Unicode/custom/embedded fonts, ToUnicode mappings, forms, layers, any marked content, semantic replacement text, nested Form XObjects, inline images, external graphics-state fonts, unsupported operators or malformed objects refuse the entire item. Unsupported files receive individual errors; no truncated/partial extraction is exported. The installed WinAnsi mapping asset was inspected as source data: no byte-code aliases occur in this version, including ordinary space. Unknown/ambiguous glyph mappings refuse the source.

Literal TXT follows content-stream order, adds explicit physical page markers, and does not reconstruct columns, tables, positioning, numeric glyph-spacing adjustments or semantic reading order. It does not perform OCR or claim general PDF-to-text fidelity. The native result is sealed to source SHA-256, output SHA-256, UTF-8 bytes, exact scope and notices. Text limits are 500 pages, 500 streams per page, 16 MiB decoded content per page, 64 MiB decoded content total, 200,000 tokens per page, array/literal depth 16, graphics depth 64, 1,000,000 extracted characters and 2 MiB UTF-8 output. Existing contained engine allocation/wall-time/termination/cleanup budgets remain mandatory, with no unrestricted fallback.

The renderer shows literal TXT in 50,000-character sections, verifies its native hash, requires visiting every section before the review checkbox can be used, and exports the complete native output. PDF copies are reviewed through exact byte/size/source hashes and filename/action scope; they are not reparsed or rendered by this queue. Current contents are unchanged. Skip/discard, retry, reorder, cancel, per-file status/error/warning and saved queue reports are included. Saved files remain after cancellation. Snapshot sessions expire after 30 idle minutes, with queue actions refreshing their lifetime; queue review state is memory-only.

Output directories/paths are never supplied by the renderer. Root wiring passes only native-picked directory paths and validated child folder names. The existing exclusive new-folder creator rechecks parent/folder realpaths and refuses link changes; filenames are bounded single components with reserved Windows names refused. Keep-both tries up to 99 exclusive filenames, never overwriting a source or existing file. Every save rechecks the source hash before folder preparation and again before writing, verifies the saved output hash via `FileStore.saveCopy`, and rechecks the source after writing. A source that changes during writing produces an explicit saved-copy warning: the output still matches its previously authorized immutable snapshot. Source snapshots themselves are never modified.

Main only imports the inert `batch-pdf-text-validation.cjs` result validator. The PDF parser lives in `batch-pdf-text-codec.cjs`, loaded only by the contained child entrypoint. `BatchDocumentActions` reuses existing queue/session/directory/cancellation machinery and owns `BatchTextService`, with observed disposal/restart required. Root owns shared main/preload/app/engine/sandbox/security-status wiring.

Integration: `BatchDocumentActions.select(paths)`, `bytes(token,id)`, `destination(token,nativeDirectory,newFolderName)`, `build(token,id,jobToken,{action:'copy'|'text',name})`, `save(store,token,id,jobToken,{reviewed:true,sha256})`, inherited `cancel/discard/clear`, `report`, `dispose`, and `status`. Child handler: `extractBatchPdfText(bytes,{})` under `batch-pdf-text`. Renderer: `BatchDocumentActionsWorkspace({announce,onClosed})` with `open()` and `prepareDeparture()`.

Files: `desktop/batch-document-actions.cjs`, `desktop/batch-pdf-text-codec.cjs`, `desktop/batch-pdf-text-validation.cjs`, `src/batch-document-actions-workspace.js/.css`. Source syntax checks only; no runtime, fixture, PDF extraction, export, app/browser, or native job was run. Root owns combined compilation. Broader font/Unicode/complex PDF extraction, other conversion actions and combine queues remain F27 work.
