# Reviewed batch compression queue

Saved implementation, 2026-10-04. Files and Workspaces expose a native-selected queue of up to ten PDFs, at most 100 MiB combined. Each source is a bounded immutable SHA-bound snapshot; no folder scan or automatic recent-file entry occurs. Queued files can be reordered, skipped or retried. Snapshots expire after 30 minutes without a native queue action.

The user chooses lossless or supported JPEG-image compression and one new output folder below an explicitly chosen native parent. The folder is created only when the first reviewed copy is saved. The queue uses the existing compression engine one item at a time and pauses at each original/prepared PDF page preview. Actual output bytes reopen in the reader for page count, page geometry and every page's operator list. Preview canvases are capped at 2 megapixels each, page waits are timed and a failed page preview disables saving. The review checkbox confirms the user's visual quality/size inspection; the implementation does not prove that every page was visually inspected.

Saving rechecks the chosen original on disk, consumes native-owned output matching the job/source/output seals, and writes exclusive copies with keep-both names. Existing originals and files are not overwritten. The new parent/folder identity is rechecked; saved bytes are SHA-verified on disk by the shared copy writer. Output is at most 100 MiB and 500 pages. Signed/encrypted/XFA/unsupported files retain the existing engine refusals. Lossless output may grow; JPEG mode changes image quality.

Stop/close invalidates owned previews, cancels processing, awaits the pending item and clears source/output buffers. Successfully saved copies remain. Native queue reports can be explicitly saved as inert JSON with chosen paths, fingerprints and item states. These contain unencrypted filenames/locations. Reports are not resumable recipes; queue state is currently memory-only. Native report order retains picker order, while the visible processing queue can be reordered. Reader-only preview failures may appear as discarded/skipped output in the native report; native compression failures have native failure reasons.

This reuses the existing qpdf sandbox and compression analysis workers. It does not claim that all analysis workers now have OS containment. Full batch workflows, persistent recovery, other operations and release-level containment remain open. Source syntax and combined compilation passed; no application, broker, worker, browser, print or runtime tests were launched.
