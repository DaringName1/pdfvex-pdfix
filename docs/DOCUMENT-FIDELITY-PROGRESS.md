# Document workspace table preservation

Saved implementation, 2026-10-04. Runtime testing remains deferred at the user's request; syntax checks are the only verification performed for this slice.

The Word/Google Docs-style editor now contains editable table, row, header-cell and body-cell nodes. A Tables panel inserts a chosen grid with an optional header row, adds/removes rows and columns, merges rectangular cell selections, splits merged cells, toggles row/column headers and applies/clears cell fill. These operations use the installed ProseMirror table commands and cell-selection plugin, with the editor's existing undo/redo history. Tab/Shift+Tab move between existing cells without creating unbounded rows.

DOCX import retains Mammoth's supported table structure, row/column spans and paragraph/list/inline text rather than stripping table HTML. Sanitized clipboard HTML follows the same path. Parsing rejects nested, overlapping, incomplete or oversized table grids before editor creation; imported scripts, external image links, event handlers and arbitrary styles remain omitted. The existing import summary explicitly says table widths and original border styling are simplified. Every document-changing transaction is bounded before dispatch, and initial JSON is validated before the workspace accepts it.

DOCX export now constructs real Word tables and cell spans, including header-row repetition, header styling, chosen cell fill and formatted cell content. Tables fit the current page's available width using an explicit equal-column grid; imported widths are not represented as preserved. The installed docx library inserts vertical continuation cells for the declared row spans. Document PDF export renders validated tables with spans, header/fill styling and cell text in the existing isolated local print renderer. Recovery drafts and version history retain and validate the same table JSON. TXT and RTF copies flatten tables into visible tab-separated rows, keeping covered span positions empty; they are not table-preserving formats in this implementation.

Bounds: 100 rows and 32 columns per table, 3,200 logical grid cells per table, 50 tables and 20,000 total logical grid cells per document; existing 20,000-node, 64-depth and 2 MB editor/recovery bounds also apply. The browser and native table validators contain the same geometry rules. Malformed span attributes and unsupported nested tables fail instead of silently dropping nested cell content.

Changed files: `src/document-editor.js`, `src/document-codec.js`, `src/rtf-codec.js`, new `src/document-table-model.js`, `src/document-tables.js`, `src/document-tables.css`, `src/document-html.js`; `desktop/document-pdf.cjs`, `desktop/recovery-store.cjs`, new `desktop/document-table-validation.cjs`. No new IPC API, package or dependency is required.

Remaining fidelity gaps include inline/floating images, original table borders/column widths, nested tables, page-accurate Word pagination, section/header/footer/revision preservation, table formulas and full Word/Google Docs acceptance. Runtime verification still needs real DOCX import/export/reopen cases with horizontal/vertical spans, empty continuation rows, repeated headers, cell selections and undo, recovery restoration, clipboard limits and multi-page PDF table rendering. These are pending and must not be treated as proven by syntax checks or compilation.
