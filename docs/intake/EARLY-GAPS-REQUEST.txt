Based on the plan and mockup, these are the gaps worth adding to PDFix’s requirements. I can’t see the code Codex is building, so this is a checklist against the idea—not a verified code review.
1. Protect work: autosave, undo/redo, recovery after a crash, and a way to restore an earlier version.
2. Prevent accidental loss: warn before closing with unsaved edits; save a copy by default; let people choose where converted files go.
3. Compare files: show two PDFs side by side and highlight what changed.
4. Handle batches: convert, compress, rename, or combine multiple selected files, with progress and a cancel button.
5. Make printing dependable: preview the result, select pages, choose size and orientation, and catch common print-layout problems.
6. Make sharing easy: export a copy, share through Windows, or copy a link only when the user has chosen a cloud service.
7. Support accessibility: keyboard shortcuts, screen readers, clear focus indicators, scalable text, readable contrast, and searchable/copyable text.
8. Clarify format support: show Open, Preview, Edit, and Convert separately for each format. Include honest limits for Apple Pages/Numbers/Keynote, older Office files, and other formats that may not convert cleanly.
9. Cover useful file types: common Office documents and spreadsheets, photos such as HEIC/HEIF, TIFF, WebP, and BMP, plus Markdown, JSON, XML, YAML, and CSV. Treat less common types as future additions unless tested.
10. Make OCR trustworthy: let users choose a language, review and correct recognized text, and warn that handwriting or poor-quality scans may be inaccurate.
11. Protect against bad files: handle damaged, password-protected, unusually large, or unsupported files without crashing or overwriting the source.
12. Protect AI use: let users choose the files and provider for each request; confirm before sending files to an online AI; show source pages or lines; require approval before edits or exports; treat instructions found inside documents as untrusted content.
13. Show connection details: clearly label local versus online AI, explain that provider accounts or API billing may be separate, and let users test or remove connections.
14. Fit Windows well: installer and uninstaller, Open With support, file associations if the user opts in, Explorer right-click actions, and an option to make PDFix the default PDF reader.
15. Test real documents: verify opening, saving, OCR, conversion, compression, redaction, forms, and printing with varied sample files. Confirm redacted information is actually gone from the saved file.
16. Prepare the logo: make app-icon, light-background, dark-background, and monochrome versions of the PDFix logo.
The additions I’d tell Codex about first: recovery and version history, compare, batch actions, accessibility, Windows integration, and safe handling of document content sent to AI. The rest can be staged as the app grows.

Yes. Here’s a deeper gap check. These are details the current plan could spell out more clearly; they don’t all need to go into the first release.
Reading and navigating PDFs
1. Bookmarks and document outline: show a PDF’s built-in sections, links, page labels, and table of contents. Let users add their own bookmarks.
2. Different page views: offer single page, two-page spread, continuous scroll, fit-to-width, and fit-to-page. Let users rotate a page for viewing without accidentally changing the saved file.
3. Links and attachments: make links easy to follow, but ask before opening an external website. Show files attached inside a PDF and let the user save them without automatically opening them.
4. Copying from complicated pages: handle text in columns, tables, footnotes, and captions in a sensible reading order; allow users to select a region when automatic selection gets it wrong.
5. Huge documents: load pages as needed, show progress, let users cancel long tasks, and avoid making the whole app freeze.
Scans, forms, and signatures
6. Scan cleanup: detect sideways or crooked pages and offer rotation, deskewing, contrast cleanup, and blank-page removal before OCR.
7. OCR review: show which words were uncertain and let users correct them. OCR quality can vary, so PDFix should not present uncertain text as exact. Adobe’s current scan workflow includes language selection and tools for correcting recognition errors.
8. Scanned paper forms: detect likely fields and help users place text and checkmarks even when a form has no interactive fields.
9. Form behavior: preserve field values, calculate fields when supported, show required unanswered fields, and keep tab order usable. Clearly identify forms the app cannot safely fill.
10. Different kinds of signatures: distinguish a typed or drawn signature from a certificate-based digital signature. Show whether an existing signature validates, and warn if an edit may affect it.
11. Annotations: preserve comments and highlights when saving or converting. Let users hide, show, print, flatten, or export annotations without confusing them with the document’s original content.
Editing, conversion, and document fidelity
12. Compare more than text: compare page order, text, images, and scanned pages; let users review changes side by side. Scanned pages may need visual comparison as well as text comparison.
13. Conversion choices: let users choose what to preserve—links, images, page size, bookmarks, or form fields—and explain when those things may not survive conversion.
14. Images from Apple devices: account for HEIC/HEIF orientation and metadata. For a Live Photo, identify whether the still image and motion clip are both present, and let users export them separately.
15. Document standards: consider optional PDF/A output for long-term archiving and an accessibility check for tagged PDFs. Accessible PDFs rely on structure such as tags and reading order; visual appearance alone doesn’t provide that structure.
16. Safe file extraction: if PDFix supports ZIP or embedded files, show what’s inside and ask before extracting. Never run extracted files automatically.
AI, privacy, and recovery
17. AI that can see page layout: some questions depend on charts, diagrams, or page images, not just extracted text. Show whether the selected model can read images, and label answers based on OCR as uncertain when recognition is weak.
18. Safe AI handling: treat instructions inside a document as document content, not commands for the agent. Keep AI in read-only mode unless the user approves a specific change.
19. Privacy cleanup: let users clear recent-file history, remove temporary files, and see whether any data was sent to an online provider. Avoid putting document text in diagnostic logs.
20. Recoverable operations: save before risky changes, keep a recoverable original, and clearly distinguish “rotate this view” from “rotate and save these pages.”
21. Bad conversion recovery: let users compare the converted copy with the source and discard the output without losing the original.
22. Duplicate files: warn gently when the user may be saving a second copy with the same name, and offer clear choices such as replace, keep both, or choose another folder.
For the requirements Codex is working from, I’d add these first: bookmarks and page views, OCR cleanup and review, safe form/signature handling, preservation of annotations and document structure, visual comparison, and recovery of originals. The rest can go into later phases after the core app works.
