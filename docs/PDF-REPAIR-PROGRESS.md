# A25 — reviewed PDF structure repair to a copy

Implemented a real bounded repair route for sources with recoverable qpdf structure warnings and a complete independently parsed preservation baseline. The source may have failed the reader's PDF.js opening. Unsupported damaged sources still receive actual diagnostics, and repair is explicitly declined when baseline evidence or safety checks are unavailable. This is a supported repair slice, not general recovery of damaged PDFs.

The main service runs pinned qpdf 12.4.2 through the existing Windows AppContainer/Job Object broker. Fixed source `--check` diagnostics retain warning exit 3. A separate pinned document AppContainer parses current source objects, refuses encryption/signature/certification/permission/XFA/invalid/unresolved structures, and records page geometry, deterministic document graph fingerprints, disconnected non-structural objects and encoded stream payloads. The renderer must acknowledge the baseline and unverified differences before rebuilding. Fixed rebuilding uses `--stream-data=preserve --object-streams=preserve --preserve-unreferenced --remove-unreferenced-resources=no`. Output must pass `--suppress-recovery --check` with exit 0, plus an independent document engine reopen with matching baseline evidence. No unrestricted worker/process fallback is used.

The actual output opens in the existing PDF reader and checks its page count/crop/rotation/UserUnit and permissions against independently retained output evidence. Original/output artwork and selectable-text comparison is offered wherever the original reader parsed; unavailable original artwork is stated. Saving requires a separate review acknowledgement, source/token/hash binding and main-process exclusive new-copy save/disk verification. The retained original is unchanged.

Source/output each remain limited to 100 MiB and 1–500 pages, 100,000 parsed objects, 300,000 canonical inventory visits/80 depth, 64 KiB diagnostic output per qpdf invocation, isolated memory/process/wall-clock limits and bounded whole-report sizes. This is whole-file processing; giant-file repair remains future work. Native staging is checked for reparse paths/unknown files, source fingerprints are rechecked after commands, owned jobs are cleaned on finish/restart, cancellation waits for observed broker exit, and unobserved termination retains staging and closes the service.

Preservation evidence excludes cross-reference/object-stream container bytes, stream Length entries, trailer ID, original byte revisions, missing bytes, and semantic/rendering correctness. Recoverable malformed cross-references do not prove recovered content was historically complete. Missing bytes are never claimed restored. A missing complete independent baseline prevents repair, including heavily damaged sources. Strict qpdf syntax checks do not certify semantic content or standards compliance.

Official command behavior was checked against [qpdf's command-line manual](https://qpdf.readthedocs.io/en/stable/cli.html) and [official manual source](https://github.com/qpdf/qpdf/blob/main/manual/cli.rst): recovery is heuristic; exit 3 denotes warnings, exit 2 errors; suppress-recovery disables reconstruction; preserving unreferenced objects and encoded stream data are conservative write settings.

Validation for this implementation is source syntax checking only, per user instruction. No application, UI, PDF, fixture, or runtime acceptance tests were executed. Packaged runtime/isolation acceptance and independent security review remain pending.
