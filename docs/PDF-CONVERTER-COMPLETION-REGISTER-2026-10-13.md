## Decoder evaluation notes

- [libheif upstream](https://github.com/strukturag/libheif) documents HEIC decoding via libde265 by default, configurable codec subsets and LGPL distribution. A pinned decoder-only build and its backend license/source/distribution records need evaluation; do not infer that a generic npm wrapper includes a current or accepted decoder.
- [Microsoft HEIF codec documentation](https://learn.microsoft.com/en-us/windows/win32/wic/heif-codec) states HEVC/AV1 codecs may be absent on a PC. A WIC-based route would require runtime detection and machine-specific acceptance; OS availability cannot be presumed.
- [LibreOffice's parameter documentation](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html) supports `--convert-to` with explicit filters/output directory and isolated user profiles. Its [license information](https://www.libreoffice.org/licenses/) is a starting point for distribution review. This machine's `soffice` command and default Program Files executable were absent; no office engine was installed or invoked.
- A machine-local FFmpeg 9.0 full build exposes HEVC decoding and was built with `--enable-gpl --enable-version3`. That is only executable inspection; no HEIC decoding fixture, portable containment or shipping license decision was made. It is not a PDFix dependency.
