# Formatted default DOCX band reopening

The contained DOCX inspector now emits either the existing `{text, align}` band descriptor or the version-1 inert formatted band model directly in `report.bands.header` / `footer`. The latter has `paragraphs: [{align, runs: [{text, font, size, color, bold, italic, underline}]}]`, bounded by the shared model to six paragraphs, sixteen runs per paragraph, 800 total characters and 200 characters per run. Font choices are Arial / Times New Roman / Consolas; sizes are 8–24 pt in half-point increments. No raw XML, relationships or field cache reaches the parent or renderer.

Direct paragraph alignment and explicit run fonts, sizes, RGB colors, bold, italic and single underline reopen as editable formatted bands. The root export's `bCs`, `iCs`, `szCs` and character-set font aliases are accepted only when they agree with the corresponding supported direct format. Unsupported inheritance, theme colors, character-specific shaping, links, images, revisions, tables, tabs and wrapped structures are refused or use the existing disclosed plain-text fallback where that fallback already supports the source. Imported source spacing, inherited defaults and absolute placement are explicitly disclosed as simplified.

Separate standalone PAGE / NUMPAGES paragraphs, including optional MERGEFORMAT instructions and cached results, are omitted with a specific notice while supported authored band paragraphs remain. Only whitespace and slash separators outside those fields are accepted. Inline fields mixed with authored text, unknown fields and malformed/nested fields remain unsupported; cached page values are never frozen as text. Automatic page numbers remain disabled on DOCX import.

Parent validation invokes only the pure rich-band validator or its existing plain descriptor checks. Renderer import installs rich descriptors in `layout.headerBand` / `footerBand` and clears the corresponding legacy text; plain descriptors clear the corresponding rich band. Single default body sections retain the existing first-page / even-odd / section-variant omission notices.

Integration requires the shared desktop and renderer band-model modules and layout validation supplied by the parent implementation. The existing report transport and `importedBandLayout` call sites need no schema-version change. Source syntax checks only were requested; no app, native engine, test suite or runtime import was launched for this change. Round-trip runtime verification remains outstanding.
