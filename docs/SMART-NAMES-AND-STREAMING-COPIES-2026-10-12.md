# Filename suggestions and disk-backed copies — October 12, 2026

F59 is connected to the Pages workspace, PDF tools and command finder. The naming dialog proposes editable Windows-safe names from available metadata, already extracted permitted current-page text, an unambiguous date, or the source filename. Every proposal explains its source. It does not rename an original or include unsaved editing changes. A reviewed name and native destination chooser precede an exact unchanged copy.

For retained disk-backed PDFs, FileStore now copies the immutable local source in at most 1 MiB chunks. It keeps the PDF on disk, verifies the expected source fingerprint and the streamed output hash, flushes the output and independently reads it back before exclusive publication. The operation checks cancellation and retained-source identity throughout copying and verification. Cancellation removes only its owned staging/output file. Existing destinations and source aliases remain refused. Progress and cancellation are connected to the naming dialog; renderer loss and application shutdown abort active named-copy jobs.

The streaming route checks destination free space with a 64 MiB reserve and fails with a reason when the available space cannot be established. This is an unchanged byte-copy route, including existing signatures/encryption, rather than a parser-based transformation. It does not remove the current whole-file limits of prepress, editing, extraction or other transforming tools. A large copy can still fail on disk space, permissions, changed source, locks or unsupported destination behavior.

Remaining implementation/verification: reviewed OCR metadata naming, expanded language/date heuristics and naming recovery; full native picker/dialog/progress/cancel UI checks; cloud/lock/disk-full/hostile-path and device cases; measured memory and responsiveness on real large drawings. The generated streaming-copy fixture is recorded in the batch checkpoint separately and cannot establish universal large-PDF support.
