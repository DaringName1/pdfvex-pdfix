# Native PDF combination progress

The standalone preserving combination workspace is implemented in `src/pdf-combine-workspace.js` and its model/style modules. The native codec, schema validator and service live in `desktop/pdf-combine-{codec,validation,service}.cjs`. Main/preload and contained-engine wiring are owned by the integration change.

## Implemented contract

- Only native-selected, retained immutable source snapshots enter the service. Renderer requests contain approved source IDs, a fresh preview token and physical-page map; renderer paths/bytes never enter the source request. Native save retrieves the sealed output by session/token and rechecks exact source identities and output hashes.
- Sources travel in a bounded binary `input.bin` packet: `PDFIXC01`, a big-endian metadata length, canonical per-source ID/name/length/SHA-256 metadata, then raw PDF bytes. There is no source base64 in the JSON request. Limits are 10 sources, 96 MiB total original bytes, 100 MiB packet/output, 500 total physical pages, 100,000 total source objects, and 10,000 total annotations, fields, bookmarks and named destinations. Receipts contain at most 500 page mappings and 10 source metadata rows, well below the contained reader's 300,000-node JSON limit.
- This slice includes every source page exactly once, in any cross-source permutation. Omitting or duplicating a page is rejected, so no source field, outline or link can quietly point to an omitted active page.
- Every original indirect object is copied into a distinct object-reference namespace, including encoded stream payloads, resources, annotations, widget appearances, private fields and inactive source catalog/metadata objects. The first source supplies the output's active metadata and viewer defaults. A fresh catalog and page root make all mapped source pages active.
- Only declared source dictionary fields change: physical page parent and materialized standard inherited values; resolved local destination fields; source form root parents and bounded default appearance font names; source top-level outline parents. A recursive construction manifest proves all other direct and indirect object data unchanged, including nested direct annotation dictionaries. The exact constructed graph is independently reloaded in the contained child, and every indirect-object fingerprint, physical page identity/order, geometry and trailer is compared before release.
- Supported local named destinations are both retained under `SourceN::name` keys and converted to explicit page-reference destinations at local actions/links/bookmarks. Understood bookmark hierarchies become source-named groups. Source form roots receive `SourceN` field namespaces, bounded default font dictionaries receive unique names, inherited default appearance/quadding and calculation order are carried, and existing appearances remain intact.
- UI sources are independently loaded with PDF.js, copy permissions are checked, and source/output geometry, annotation values/local targets, field namespaces, and grouped bookmark hierarchy/targets are compared. Actual original/combined pages render side by side. Every output page must be viewed and the preservation limits acknowledged before the token-only save action becomes available. This is implemented product verification, not an executed test.
- Service cancellation clears matching output seals, aborts the contained operation, awaits the engine promise and observed termination/cleanup, and closes on unsafe cleanup. Preview render tasks and loading jobs are destroyed/awaited. Closing waits for cleanup before releasing the editor guard; cleanup failures remain visible.

## Explicit refusals and remaining scope

Encrypted, permission-constrained, signed/certified, XFA, tagged, layered, positional page-label, article, portfolio, unknown active catalog/name-tree, unsupported form resource/action/default-appearance, malformed/shared/cyclic page/form/outline and unsupported local destination structures are refused. Standard external actions and private data can remain in a preserving copy; combination is not sanitation or proprietary application fidelity verification.

Partial extraction/insertion with semantic pruning of form trees/bookmarks/destinations, duplicate-page annotation identity policy, arbitrary form appearance content parsing, non-font form default resources, optional-content/structure-tree merging, page-label remapping, non-destination name-tree merging, portfolios and application-specific catalog extension reconciliation remain unfinished broader F06/F07/F28 scope. The existing regular page workspace's renderer reconstruction is not promoted to a trusted preserving native workflow by this change.

## Validation boundary

Only source review and JavaScript syntax checks were performed for these modules. No PDF parsing/execution, UI/native/device runtime tests, fixture creation or new tests were run. Integration compilation is performed by the root task after source freeze; it does not constitute runtime fidelity validation.
