# Contained native FDF comment exchange — October 9, 2026

Supported standard comment exchange is coded and integrated, not yet accepted against real Revu/Acrobat files. Import and export are available in the reader tools and command palette. This is a comment adapter; FDF form-value submission and full FDF compatibility remain unfinished.

Export uses the fixed contained source-comment inventory and at most 1,000 explicitly selected occurrences. The child maps supported Text, Line, Square, Circle, Polygon, PolyLine, Ink, Highlight, Underline, Squiggly and StrikeOut comments into actual FDF 1.2 indirect objects, classic xref/trailer and EOF, with Unicode hex literals. A separate bounded grammar readback compares each encoded annotation dictionary. The renderer shows actual output, individual result/omission receipts and source hashes before a native token-only exclusive save. Existing private fields, rich text and appearance payloads are not claimed preserved by this exchange.

Import reads a user-chosen regular FDF under 8 MiB through a native file picker, retains exact selected bytes and binds their hash to the chosen PDF. The child parser accepts a bounded inert FDF 1.2–1.7 single-revision object grammar, at most 1,000 comment dictionaries, 10,000 objects, 100,000 parsed nodes and depth 16. Streams, filters, active/resource containers, appearances, encryption and incremental revisions are refused. The parser accepts supported PDFDocEncoding/UTF-16BE literals. Target-file and ID claims are ignored and never retrieve or authenticate a document.

Understood dictionaries adapt to the existing preserving XFDF native import helper. The proposal lists supported and omitted records, geometry, claimed author/text/reply/state data and unmapped fields. At most 200 selected records are added per prepared copy. The child independently checks retained original PDF structures and added annotation receipts. The reader compares actual changed pages and verifies original/new annotation identities and geometry before saving; every changed page and all result pages require explicit review. Gray/RGB color quantization, unsupported border/style fields and private data omissions are disclosed. This is not a promise of identical custom Bluebeam appearances or provenance authentication.

Main-retained import/export seals have separate output kinds, source IDs, tokens, source fingerprints and output hashes. New selection, invalidation, cancel, source departure, renderer failure and shutdown invalidate relevant receipts. Cancellation and close await native discard/termination; cleanup failure keeps the workspace guarded and closes the unsafe service. Originals and existing output filenames are never overwritten. Imports use the fixed 12 MiB request envelope and ordinary exports 2 MiB; output/report/schema limits apply.

Root completed lifecycle integration and documentation after the delegated agent stopped at a usage limit. Source syntax and integrated renderer/native compilation passed; no runtime, UI, PDF/engine, Revu/Acrobat, performance or security tests were run. Remaining F21/B05 scope includes wider FDF structures/form data, custom appearances, BAX/BTX/private Bluebeam adapters and actual interchange acceptance.
