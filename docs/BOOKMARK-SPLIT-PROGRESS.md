# PDFix bookmark split implementation

Saved October 7, 2026. Adopted F05 expansion, coded; app/runtime acceptance remains deferred.

The existing **Fix or combine pages → Split into files** dialog now offers **Document bookmarks**. Choose one loaded original and top-level bookmarks, through level 2, or through level 3; read its internal destinations before building. Named destinations and actual page references resolve through PDF.js. Printed page labels, title text, external links, and actions are never treated as page numbers or fetched.

Resolved physical source pages map to every occurrence in the current arranged output. Starts sort by current output position; duplicate starts merge explicitly, and duplicate page occurrences each start a section. A prefix group is inserted when needed. Every current output page belongs to exactly one group, including pages from other combined originals; source-page removal, invalid/external destinations, ignored deeper entries, merged starts, repeated pages, and the prefix are disclosed. A result with no usable starts or fewer than two files is refused.

Before export, a section review lists the actual `part-001.pdf` / `part-002.pdf` names, bookmark titles, output ranges, and expandable exact output-to-source physical-page mappings. Titles are descriptive labels, not filenames. Existing split builds, output readers, original comparison, review checkbox, exclusive new-folder export, and cancellation remain in use. All source byte snapshots remain unchanged; current crop, resize, rotation, and page order are preserved through the existing writer. Existing page-copy limitations remain disclosed: annotations, links, bookmarks, and document metadata are removed; forms/signatures/protected sources are refused, and crop is not secure removal.

Outline reading is bounded to 500 source/output pages, 2,000 outline entries, 20 hierarchy levels, 5 seconds per PDF.js read, 60 seconds total, 50 detailed skipped/merged notes, 200-character bookmark labels, and a 100 MB source. Exceeding structural/time limits refuses the recipe rather than silently truncating section boundaries. The existing writer separately enforces up to 10 inputs, 100 MB combined input/output, 500 files/pages, valid nonoverlapping groups, and its two-minute worker limit. Close/cancel aborts outline reading, destroys its loading task, and invalidates in-flight results.

Saved page recovery/workflows store the **resolved custom physical output ranges** using the current validated recipe schema. Reopening does not silently reread a changed outline or promise to persist bookmark titles or depth/source selectors. To compute new boundaries, choose Document bookmarks and read again. No native broker, main/preload IPC, dependencies, or persistence schema changes were required.

Files: `src/bookmark-split-model.js`, `src/split-workspace.js`, `src/split-workspace.css`. `node --check` passed for both changed/new JavaScript modules. No app, fixture, browser, native worker, or export run was performed. The root agent owns combined compilation. Size-based splitting, broader reusable preset management, wider preservation, and runtime acceptance remain F05/F06 gaps.
