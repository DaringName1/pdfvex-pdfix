# Original embedded-font glyph expansion

Saved October 7, 2026. Adopted F10 original-text editing expansion is coded; runtime/corpus acceptance remains deferred.

Previously, supported embedded fonts could only reuse characters already observed in editable source text. Replacement encoding now also accepts independently proven existing characters that have not yet appeared in those runs. This is a real extension of original text replacement: it changes the original supported content operand using the original font/code/size, not repainting, overlay text, substitution, font injection or redaction.

The new path applies to horizontal Type0/Identity-H fonts with one CIDFontType2 descendant, an embedded FontFile2 single TrueType `glyf` program, and an already declared bounded ToUnicode code mapping. Prefixed subset font names are refused. Absence of a subset prefix is not a certification that the font is a complete upstream font; every newly authorized character still needs its actual glyph/outline/metrics proof. Original observed-glyph editing remains available if expansion fails or is unsupported.

For each candidate existing code, the helper independently checks that the declared scalar Unicode value maps to the same nonzero GID through the embedded Unicode `cmap` (formats 4/12, Unicode or Windows Unicode records) and the PDF CIDToGIDMap (explicit mapping or Identity/default Identity). Conflicting Unicode maps, missing or out-of-range GIDs and ambiguous code choices refuse that expansion. TrueType `head`, `maxp`, `hhea`, `hmtx`, `loca` and `glyf` bounds/geometry are checked. Horizontal advance must agree with PDF `W`/`DW` to within 0.5 units per 1,000, allowing the PDF integer rounding of an otherwise proven metric. New codes must have positive advance and a valid complete simple outline, or an actual blank outline for Unicode space characters.

Simple outline checks cover contour endpoints, instruction-byte bounds, repeated flags, coordinate encodings/deltas, point bounds and small zero padding. Each GID outline is parsed once per font. Compound glyphs are currently refused for new-character expansion. Unicode marks/controls/formatting, contextual scripts, shaping, arbitrary text reflow, vertical writing, CFF, variable, SVG, color and bitmap font programs remain unsupported. The accepted scalar scripts are Latin, Greek, Cyrillic, Common, Han, Hiragana and Katakana; this does not imply linguistic shaping or semantic layout support.

No source font dictionary, ToUnicode stream, CIDToGID mapping, font program, widths, resources or other text run is modified. The existing `originalFontProof` fingerprint still verifies the exact original dictionary/reference/stream graph before and after save. Encoding prefers a code already present in the edited run, otherwise a unique observed code, otherwise a unique independently proven existing code. Ambiguous alternatives refuse instead of guessing. Existing source-page/nested-Form paths, operand-span replacement, spacing numbers, source hashes and final output review remain in use.

This deliberately does **not** allocate codes for a Unicode character absent from the original ToUnicode map, extend CIDToGID/W, embed new outlines, rewrite font programs or update font resources. That broader capability needs an explicit allowed-font-object-change preservation contract, source/output glyph mapping verification and a writer that can preserve every original code/resource alongside new entries. Current save acceptance requires the entire original font object graph unchanged; silently weakening that proof would be incorrect.

Budgets: 16 MiB requested decoded font-program size, 32 MiB program reads per inspection, 64 sfnt tables, 64 cmap records, 8,192 format-4 segments, 65,536 format-12 groups/GIDs, 16-bit CID bounds, 65,536 expanded width entries, at most 1,024 simple contours / 65,536 points per glyph. Existing ToUnicode limits (1 MiB per map, 8 MiB combined, 16,384 codes per font, 65,536 codes combined, 200 fonts) remain in place. These are parser/result budgets, not a claim of effective OS allocation containment for this older PDF-editing route.

Files owned here: `src/pdf-truetype-glyph-proof.js`, `src/pdf-original-font-map.js`. Root shared UI/inspection wiring can expose `sourceFont.expansion.characters`, count proven characters absent from `sourceFont.observed`, and `sourceFont.expansion.scope`; an availability count is not a promise every Unicode character or every embedded font is editable. JavaScript syntax checks only; no PDF/font runtime, fixture, app launch or new tests were run. Root owns combined compilation and central status documents.
