# Reviewed form calculations — October 9, 2026

Integrated source adds user-authored declarative rules to Fill and sign. Supported operations are sum, product, average, minimum, maximum, ordered difference, ratio and percentage. Rules reference eligible existing nonsensitive editable fields; targets must be supported editable text fields. Existing PDF calculation/validation/formatting/button actions are inventoried inertly and never run.

Users choose inputs, an explicit blank policy and 0–6 decimal places, inspect current source values and proposed results, check a review box, then apply. Rules never apply automatically and are not embedded as executable PDF formulas. Dependencies are calculated in topological order; cycles, unknown/unsupported/sensitive fields, ambiguous or multiselect numeric values, invalid plain decimal strings, division by zero, one-trillion magnitude limits and target length failures are explicit errors. Calculations use binary JavaScript number arithmetic and decimal formatting; financial/precision-sensitive results require independent review.

Recipes join existing undo/reset and local source-bound recovery drafts. The native recovery validator is generated from the same pure model. Changing any current value/rule invalidates the reviewed receipt; filled-copy authoring independently requires rule target values to match a fresh evaluation. Existing output reopen, page preview, comparison and exclusive copy-saving flow stays in use. Password/read-only/calculated source fields remain unsupported targets. No document-origin code, ambient file/process access or network operation is added.

Whole-app compilation completed with 288 modules; 23 root/delegated integration source files passed syntax checks. No runtime, document, UI, precision, recovery or adversarial test was run. This is implemented groundwork for F18/A14; broader declarative document compatibility, validation/formatting rules, accessibility/tab order and isolated legacy-script compatibility remain.
