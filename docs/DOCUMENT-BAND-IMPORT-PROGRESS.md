# Plain original header/footer import

Saved implementation, 2026-10-04. This slice was checked with source syntax only. Application, worker, Office engine, broker, network, print and rendering tests remain deferred by user request; no new tests were written.

Opening an original DOCX can now populate Page setup from its supported plain default header/footer text and left/center/right alignment. Raw package, relationships and XML inspection happen only inside the existing contained document-table-grids operation. The renderer receives an inert source-SHA-bound optional `bands` field alongside table descriptors, validates its layout fields, and applies it only after existing source verification. The strict parent/child descriptor validator accepts old reports without this optional field and bounds new reports with exactly `header`/`footer`, each null or exactly `{text,align}`. Original sources are never modified. Missing inspection APIs retain the disclosed fallback.

The DOCX slice supports one ordinary final body section, default internal header/footer references, up to two paragraphs with matching alignment and at most 120 UTF-16 text characters. Each band XML and the document relationships/settings metadata are limited to 256 KiB before parsing, within the existing Office archive/XML containment bounds. Text, font/size metadata and basic paragraph metadata are accepted; source font, styles, spacing and absolute placement are simplified to the authored 9 pt Page setup presentation. Relationship targets cannot be external, absolute, traversal paths or ambiguous IDs. Unsafe or unsupported individual bands are omitted with notices. A band metadata error cannot discard successfully inspected table descriptors.

RTF import now captures ordinary `header` and `footer` destinations as separate bounded plain bands, preserving the existing body paragraph/mark parser. Its existing byte/token/group/text limits remain in force, and source band declarations are separately bounded. Text/Unicode escapes and uniform alignment are retained. One trailing paragraph terminator is removed; text is never silently shortened to fit. Multiple default declarations or section breaks cause source bands to be omitted. Band parsing does not put header/footer text into the body or change the body's current paragraph.

Imported bands use the existing authored model, recovery/version snapshots and DOCX/RTF/native PDF exports. A recovered rich draft takes precedence over original import, including old drafts whose layout defaults are filled by the existing model. Import reports with band information disable newly generated page numbering; the user can enable it in Page setup. Original dynamic page fields and cached band field values are never converted to literal stale page numbers. Bands containing fields are omitted in this small slice, including a band that combines plain text with a page-number field.

First-page, even/odd, linked or multiple-section layouts, mixed alignments, rich runs, images/tables, links, tracked text, fields, tabs, unknown rich controls and original Word pagination are not reconstructed. Default bands imported from a document with first/even/odd variants repeat on every authored page, and the warning explicitly states that behavior. The warnings show band-specific notices separately from table import notices. TXT and source-copy boundaries remain body-only.

Files: new `desktop/document-band-import.cjs`, `src/document-band-import.js`; updated `desktop/document-grid-import.cjs`, `desktop/document-grid-validation.cjs` (security agent's shared inert-schema edit), `src/rtf-codec.js`, `src/document-editor.js`. The existing contained entry/service and main/preload IPC need no new route; root owns combined compilation.

Later runtime verification must cover ordinary external DOCX/RTF bands, first/even/odd and section omissions, missing/duplicate/external relationships, malformed or oversized metadata, Unicode and literal punctuation, overlong/multiline/mixed-alignment rejection, body text and image/table import preservation, rich draft precedence, departure cancellation, Page setup editing/recovery, and DOCX/RTF/PDF output of the imported authored bands. There is no claim of complete or page-perfect Word fidelity.
