# Recoverable document table column widths

Saved implementation, 2026-10-04. This is a code/syntax checkpoint. Runtime testing, actual Office containment execution and Word/PDF layout acceptance remain deferred.

One column-width contract is now used throughout the document workspace: `table.attrs.columnGridTwips` is null for equal proportions, or an integer width for each logical column. Values are 1–30,000 twentieths of a point, with up to 32 columns; the existing table, document, depth and recovery limits remain in force. This table grid is independent of merged-cell structure and is retained by recovery/version history and sanitized PDFix table copying. Widths represent proportions fitted to the available page/cell width, not an assertion that original absolute table size or Word pagination is retained.

The selected-table controls show the grid as relative pixel widths, accept comma-separated values, apply a complete validated grid or restore equal columns. Undo restores the previous widths. Row edits and merge/split preserve the grid. Column insertion/deletion changes the grid in the same transaction as the structural edit, including selections crossing merged cells. Table display and native PDF output use colgroups with those proportions. DOCX output writes an explicit scaled integer grid and corresponding cell widths, summing the same logical columns for merged cells. Inline image export uses the resulting cell space, retaining the previous bounded image support.

DOCX grid extraction lives in `desktop/document-grid-import.cjs`, intended exclusively for the contained Office engine. It reuses the bounded Office archive/XML adapter; no new ZIP/XML parser is invoked in the parent process. The security service owns the fixed operation, output validation, source identity, limits, cancellation, lifecycle and containment reporting. The root API is `inspectDocumentTableGrids(id)` with `cancelDocumentTableGrids(id)`. Missing or failed API inspection produces an explicit equal-column fallback notice.

The inert result contains the actual source SHA-256 and up to 50 descriptors: `{key, rows, columns, widthsTwips, signature, reason}`. Declared grids are accepted only when positive bounded widths agree with source cell geometry and do not conflict with preferred cell widths. Nested, tracked/wrapped, incomplete or ambiguous table structures disclose an unsupported descriptor. A descriptor signature hashes canonical cell coordinates, spans and normalized plain text. The editor rechecks source bytes and applies a grid only if that signature is unique in both the source report and actual imported table JSON. Duplicate or unmatched tables keep the fallback and disclose it. Matching uses no ordinal guesses. Signature matching is structural correspondence, not a document authenticity or pixel-fidelity claim.

Recovered rich drafts take precedence over original-file grid inspection; imported widths never overwrite a user's saved grid. The native and browser geometry validators have matching bounds. The contained source codec remains read-only and originals are untouched.

Original borders, styles, floating layout, nested tables and page-perfect Word/Google Docs fidelity remain open.
