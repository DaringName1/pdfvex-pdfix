**Problem 2 (Ctrl+S swallowed) was not reproduced.** In the real app, Compress and Redact were opened, closed with ×,
and then Ctrl+S behaved exactly as before either tool was opened. Downgraded to "no evidence".

**Save code that is correct (deep-dive confirmation):**
- Every copy is written to a hidden temporary file, flushed to disk and re-read byte by byte before it becomes
  visible, and it never replaces an existing file.
- Save-over (Word, RTF and text only; **PDFs are never overwritten**) refuses if the file changed since opening,
  keeps a backup first, and re-reads after replacing.
- Failures clean up only PDFix's own temporary files and never delete a file another program put there.
- Drag and drop can only pass files a person actually dropped.
- Every other file operation goes through ids or tokens, never typed paths.

## Checked and found fine

- **Renderer ↔ main process:** every channel the page calls has exactly one handler, none is registered twice, and
  every bridge function is used. The four unused functions listed in KNOWN-ISSUES A17 are gone.
- **No `eval` / `new Function`**, and no program started through a shell. The 36 "exec" hits are regular-expression
  matching, not program launches.
- **HTML built from values:** all 10 places insert only fixed text or icons, never document content (file names,
  comments, bookmarks).
- **Web links:** the 4 `openExternal` calls all go through the confirmation that shows the address.
- **Timers:** the 4 repeating timers are all stopped when their tool closes.
- **Window-wide listeners:** the ones in tool files are all removed through a cleanup signal.
- **Sandbox file reads:** size-checked before reading.
- **No TODO/FIXME left, no `console.log` in the UI, no `Math.random` in the main process.**
- **Dependencies:** `npm audit --omit=dev`: 0 vulnerabilities (10-25).
