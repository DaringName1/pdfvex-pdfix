# Print marks implementation · 2026-10-12

F64 adds crop, bleed-boundary and registration marks to an explicitly selected set of physical pages. The engine entry point is `buildPrintMarks(bytes, draft)` from `desktop/pdf-print-marks-codec.cjs`, dispatched inside the fixed contained engine as `print-marks-build`. The desktop service is `PdfPrintMarksService`; its `build(sourceId, source, token, draft)` accepts the opened PDF source object and returns `{token, bytes, report}`. `output`, `cancel`, `discard`, `status` and `dispose` follow the contained decoration-service pattern. Renderer calls are `buildPdfPrintMarks(id, token, draft)`, `savePdfPrintMarks(id, token)`, `cancelPdfPrintMarks(id, token)` and `discardPdfPrintMarks(id, token)`.

The version 1 draft names zero-based selected pages, millimeter or point units, four bleed distances, mark offset, line width, one RGB ink color, three mark-type switches, and acknowledgment that MediaBox/CropBox may expand. The writer uses the selected page's leaf TrimBox where present and otherwise uses the visible MediaBox/CropBox intersection as its effective trim. When that selected page has no leaf TrimBox, the writer materializes one at the effective trim coordinates; the receipt reports `trimMaterialized: true` and independent reopening verifies the exact geometry. Existing leaf TrimBox values are retained. MediaBox/CropBox may be inherited. UserUnit is checked at the leaf on selected pages; non-default selected units are refused, while unselected pages retain their page dictionaries and units untouched. It keeps existing page content references and stream bytes and writes new vector strokes outside the effective trim area. It expands MediaBox and CropBox enough to include the marks.

The preview renders each selected page from the original and independently reopened output and reports exact TrimBox, MediaBox and CropBox coordinates, including whether it materialized an effective TrimBox. Every selected page must be reviewed before save. Build refuses signed, certified, encrypted, XFA, malformed, unsupported content-stream, unsupported box and selected non-default UserUnit inputs. The output is a new copy bound to the source fingerprint and output hash; no source overwrite is offered by this service.

The bleed settings reserve space and draw boundary marks. They do not generate or extend artwork into a bleed area. The selected ink is a single visible RGB color, not process-color separations; this work makes no claim about color management, PDF/X, PDF/A or other print compliance. Page rotations are preserved and marks use the PDF page coordinate system; unusual source graphics state can affect rendering, so compare each actual source/output page before saving. Existing TrimBox geometry is not altered.
