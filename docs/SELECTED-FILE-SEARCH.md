# Local search across explicitly chosen files

Saved source implementation, 2026-10-04. Runtime testing is deferred by user request.

Search selected files is available from Files, Workspaces and the action finder. The native picker accepts up to ten PDF, DOCX, RTF or supported UTF-8 text/data files. It reads only chosen sources, canonicalizes duplicate paths, retains immutable snapshots and fingerprints, and reports unreadable or unsupported choices individually. Choosing search sources does not change the opened document or add items to recent history.

Users choose which picked files to search, enter a phrase and select case sensitivity or whole-word matching. Matching collapses whitespace while retaining source offsets and literal excerpts. Results include filename and physical PDF page or source/extracted-text line, with fifty results per screen. Each file has an extraction report, including partial failures and omitted content. Opening a result explicitly reopens its original using the searched SHA-256; changed originals are refused. PDF results jump to the selected physical page. Document line references refer to saved or extracted text, not Word pagination. Opening a document exposes its Find controls with the searched phrase; source-text editors additionally select the precise result only when their entire displayed text still equals the saved source, so a restored recovery draft is not mistaken for the searched copy.

PDF.js searches selectable text locally, with its own owned loading task. Password-protected PDFs are skipped, copying restrictions are respected, and scans are not OCRed automatically. DOCX searches extracted body text; headers, footers, drawings and other unsupported content are omitted. RTF uses the supported local text adapter. Plain data files require valid UTF-8 and reject NUL/binary content. No active document content is executed or external document resource fetched.

Bounds: ten chosen files; 100 MiB combined source bytes; PDF at most 100 MiB and 500 physical pages; DOCX/RTF at most 10 MiB each; text/data at most 2 MiB each; page/extracted text at most 2 MiB, PDF text at most 50,000 runs per page; 32 MiB aggregate extracted UTF-8 text; 2,000 displayed matches; query at most 200 characters; owned extraction waits at most thirty seconds (document worker forty-five), with a two-minute per-file deadline. Native snapshots expire after thirty minutes. Cancel fences pending results by generation and destroys only owned search tasks/workers; close discards the native snapshot and results; the parent clears owned snapshot buffers on discard, expiry or renderer loss. Choosing or opening a native source must finish before departure.

The PDF and DOCX extraction workers run in Chromium's existing sandboxed renderer context, not the native contained document engine. This feature does not expand native-engine containment claims.

Later runtime acceptance must cover actual-file native picking and cancellation, duplicates, mixed formats, scanned/password/restricted PDFs, Unicode/whitespace/whole-word matching, filenames and physical references, limits/partial reports, snapshot expiry, changing originals, dirty-editor departure, worker disposal, keyboard/screen-reader behavior and result opening. Saved code and compilation do not prove these outcomes.
