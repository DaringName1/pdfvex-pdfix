# Workflow library and recovery

The editable reorder/Bates workspace can save up to 20 named step definitions in the app's user data folder. A definition stores its page count and step settings; loading it into a PDF with a different page count is refused. Saving a definition never creates a PDF. A loaded definition remains editable and requires a new native build, page review, and explicit output save.

For a selected PDF, valid edited settings are saved locally as a recovery draft keyed by the original SHA-256 fingerprint. At most 20 source drafts are retained. Recovery requires the exact source hash and page count and is an explicit action in the workspace. It restores editable settings only, without any prior preview, review acknowledgement, or output authorization. A separate Clear recovery draft action deletes it. Draft writes are debounced and serialized; close flushes a pending valid edit. Invalid intermediate settings are not written.

The store is `document-workflow-library.json` under Electron's trusted `userData` folder. It contains definition names, step settings, source hashes for drafts, and timestamps. These settings are **not encrypted**. No PDF bytes, output PDF, arbitrary user-selected file path, native receipt, or review state is stored. The store has a 128 KiB size limit, per-step validation, and atomic replacement; a malformed store is left untouched and reads/writes fail closed. Storage failures are shown in the workspace. Deletion requires pressing the explicit Delete selected workflow or Clear recovery draft control.

Native API contract: `new DocumentWorkflowLibrary(userDataFolder)` exposes `listDefinitions()`, `saveDefinition(name,pageCount,steps)`, `loadDefinition(id,pageCount)`, `removeDefinition(id)`, `saveDraft(sourceSha256,pageCount,steps)`, `readDraft(sourceSha256,pageCount)`, and `clearDraft(sourceSha256)`. The main process must derive the draft source hash and page count from the selected source, never from renderer-supplied values. The renderer bridge names are `listDocumentWorkflowDefinitions`, `saveDocumentWorkflowDefinition`, `loadDocumentWorkflowDefinition`, `removeDocumentWorkflowDefinition`, `saveDocumentWorkflowDraft`, `readDocumentWorkflowDraft`, and `clearDocumentWorkflowDraft`.
