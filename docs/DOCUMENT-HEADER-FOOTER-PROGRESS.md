# Authored document headers and footers

Saved implementation, 2026-10-04. This checkpoint contains code and syntax checks only. Real Word/RTF/PDF rendering, pagination and recovery UI verification remain deferred by user request.

Page setup now edits authored header/footer text, independent left/center/right alignment, page-number placement in either header or footer, and independent number alignment. The existing `pageNumbers` boolean remains the enable switch. Each text band supports 120 UTF-16 characters and at most two authored lines; control characters, invalid surrogate strings and XML noncharacters are refused. Text is literal, not markup, and appears at 9 pt. Page numbers use a separate line. The editor shows a header/footer band preview with a page-number placeholder; actual pagination and numbers are shown by PDF preview.

The shared layout contract adds `headerText`, `footerText`, `headerAlign`, `footerAlign`, `pageNumberPlacement` and `pageNumberAlign`. Missing fields in older layouts/drafts default to empty text, left text alignment and centered footer numbers, preserving prior defaults. The browser model and native recovery/PDF validator have the same rules. Existing recovery/version snapshots already carry the full layout, so authored bands are retained and restored through that path. No new IPC or dependency is needed.

A common margin helper reserves extra top/bottom space for the authored bands and page-number lines, using page width and a conservative bounded text-width estimate. The base left/right margin is retained. Installed fonts and layout engines still vary; final page review is required and this estimate is not a proof of pixel-perfect placement. The editor, DOCX, RTF and PDF share this reservation. Minimum small margins may grow on a side containing a band.

DOCX export now writes actual default Headers/Footers, plain text paragraphs, alignment and current/total page fields. RTF export writes authored header/footer destinations and PAGE/NUMPAGES fields with escaped literal text. Native PDF output uses escaped templates, current/total page placeholders, explicit font/alignment and reserved margins. Header/footer-only authored documents can create a PDF; an entirely empty document with only default page numbering still cannot. PDF preview retains these fields when changing its paper/font/margin settings and shows the authored band text in an inert summary.

TXT, Markdown/JSON/XML/YAML/CSV source copies continue exporting body text only. Header/footer content and page-number settings never get appended to source data. PDF copies of source text may use authored bands as presentation settings. Images, supported table grids/spans, recovery and existing body formatting are retained in their respective supported export paths.

The subsequent plain-band import slice is described in `DOCUMENT-BAND-IMPORT-PROGRESS.md`: supported single-section plain default DOCX/RTF bands now populate Page setup. Different first/even/odd pages, linked or multiple sections, header images/tables, rich header formatting, bands containing page-number fields and original Word pagination remain unsupported. Authored exported headers/footers are real format structures; only supported plain bands reimport, while rich/field-containing bands receive explicit omission notices.

Changed files: new `src/document-layout-model.js`; updated `src/document-layout.js`, `src/document-editor.css`, `src/document-codec.js`, `src/rtf-codec.js`, `src/document-pdf-export.js`, `desktop/document-layout-validation.cjs` and `desktop/document-pdf.cjs`. The existing recovery validator automatically uses the extended native layout contract. Root owns the document-save lifecycle; retaining layout recovery when saving a body-only text copy is tracked as a separate integration concern.

Later verification needs old-draft compatibility, editing/recovery/version restore, header/footer text containing literal HTML/RTF punctuation and Unicode, narrow/landscape pages and long wrapped bands, page-number placement/alignment, multi-page DOCX/RTF/PDF output, header-only documents, body/source copy boundaries and continued table/image output. No application, worker, browser or print path was launched during this checkpoint.
