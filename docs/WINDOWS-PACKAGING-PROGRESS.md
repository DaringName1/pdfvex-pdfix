# Local Windows development packaging

The saved `npm run package:windows` command compiles PDFix and creates a fresh Windows x64 development package below `releases`. `node scripts/build-windows-package.mjs` can package an already compiled matching source snapshot. No app, installer, registry/default change or runtime tests are launched by either build stage.

The package includes an Electron runtime renamed PDFix.exe, fixed contained engine/broker/qpdf and pinned notices, local PDF/OCR assets, explicit desktop/renderer modules and the installed production dependency closure. It carries a complete file/SHA-256 inventory, runtime pins, dependency/license metadata, source snapshot, completion marker, optional Open With manifest and ordinary-policy PowerShell installer/uninstaller sources. Incomplete directories get no completion marker. No recursive deletion or automatic cleanup of an incomplete package occurs.

Portable use keeps the entire app directory together. Per-user installation writes a new version/build directory below LocalAppData/Programs/PDFix, checks source/copied bytes and records files/shortcuts/registry entries. Start-menu shortcuts are created with unique build names; desktop shortcuts and Open With registration require explicit switches. Existing different registry values are retained with a visible notice. No UserChoice or extension default value is written. Versions install side by side; selecting a default remains a Windows Settings action.

Uninstall only removes recorded matching program files and matching shortcut/registry values from the explicit versioned install. It keeps modified/busy files, other builds, documents and local recovery/settings. Empty directories are deleted without recursion. Windows execution policy is respected; no bypass is supplied. These scripts have only been parsed for source syntax and have not been executed. An unsigned script may require the owner's normal approved execution-policy/signing workflow before use.

A build-source inventory is captured before/after compilation. Packaging compares that identity again before/after copying, so changing code requires a fresh compilation. Each file uses a bounded regular-file copy and post-copy SHA; source pins detect interrupted or changed inputs. Inventory checks prove copied bytes, not binary authenticity, OS isolation or clean-machine operation.

This is development packaging, not an accepted installer/beta release. Executable branding/icon derivatives, signatures, reviewed single-file installer/upgrade/update UX, complete SBOM/security/license/provenance checks, runtime launch/open/save/recovery/containment, actual install/uninstall and clean-machine/accessibility acceptance remain open. The supplied master logo is unchanged; executable metadata/icons still originate from the installed Electron runtime.
