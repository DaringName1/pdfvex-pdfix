## Contained rich documents

New desktop rich-document codec/service/validation modules expose only `rich-docx-read`, `rich-rtf-read`, `rich-docx-write` and `rich-rtf-write` in the fixed packaged engine. Source identity/SHA is checked before staging. New unsourced documents use a fixed harmless input byte to carry the reviewed rich snapshot; existing documents bind the actual opened immutable source. Rich snapshots are strictly bounded plain inert data (1.9 MB), with existing table/image/page-layout validation and node/mark/depth limits. Parent output checks validate inert shapes/headers/bounds; the parent never parses DOCX archives or RTF grammar. RTF output is parsed again in the contained child; DOCX archive structure receives its bounded child check. These checks are not full layout/semantic round-trip proof.

DOCX ZIP/XML/Mammoth parsing and embedded-asset extraction now run in the child with external file access and embedded style maps disabled. Import returns bounded inert HTML, up to 20 raw PNG/JPEG assets totaling 8 MiB/12 million pixels, and bounded notes. The parent checks types and raster headers. The renderer worker contains image normalization only: decode to bounded normalized inline PNGs, escape asset attributes, replace exact native image markers, omit unsupported assets with notes, and enforce the 2 MiB editor/recovery import bound. The editor still sanitizes returned HTML before use. Image pixels are decoded in Chromium; this does not complete OS containment of image/OCR/PDF rendering. Raw source images are not persisted in renderer storage.

Generated DOCX/RTF copy bytes remain in the trusted native save handler and use an exclusive, hash-verified new filename. Picker cancel retains editing work. Failed containment has no worker or unrestricted rich-codec fallback; unsafe cancellation/cleanup leaves the service closed. Existing format-fidelity limitations are retained. Renderer image normalization, full document import/export preservation, parser/decode corpora, rapid-close/error and actual Windows containment behavior remain untested on the changed build.
