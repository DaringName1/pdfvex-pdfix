# Scoped document health report — 2026-10-04

Workspaces and the reader offer a document health report; File details also has a Run document health report control. It uses the immutable opened PDF snapshot and its existing reader worker. It records source hash, permissions and declared metadata plus observations across up to 500 physical pages: visible size/orientation groups, nonstandard UserUnit, saved rotation, very large visible pages, permitted selectable text, replacement characters and missing reader font metadata, unresolved internal link destinations, unsupported link actions, page structure-tree presence and reader-reported alternative form labels.

Named destinations and explicit page references are resolved against the opened source, with bounded lookup and link counts. HTTP/HTTPS addresses are checked for supported syntax only. No websites, attachments or document actions are opened. Streamed text has per-page item/character/style bounds. A 120-second overall budget, per-operation waits, cancellation and page/source/generation identity guards retain an explicitly partial report if inspection stops. Observations have a 1,000-entry cap and 50-entry UI pagination. A new JSON copy contains coverage, omissions, counts, source identity, findings and unread checks, bounded to 1 MiB. Existing File details permission handling now accepts this installed PDF.js version's Set result, preserving unknown status for malformed values.

This is a first implementation of part of M08.03 and structure/form-label observations relevant to M08.01. It does not inspect embedded/missing font programs, image dimensions or compression, external link reachability, accessible reading order/headings/contrast, certificate trust, malware, prepress boxes or real printer compatibility. Missing selectable text is not called a scan or blank page. Tag presence does not establish correctness. No repairs or health/accessibility pass verdict are offered. Full master acceptance remains open.

Source syntax and compilation are the current evidence. Runtime, real-file, accessibility and printer acceptance remain deferred under the user's coding-first instruction; no inspection feature was executed by the coding agent.
